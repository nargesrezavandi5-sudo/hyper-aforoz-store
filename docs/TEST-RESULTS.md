# نتایج آزمایش سیستم (تاریخی)

تاریخ اجرا: محلی (Windows، Python 3.8.8، Node v24، Chrome داخلی)
این نتایج مربوط به اجرای قبلی پروژه هستند و جایگزین آزمون‌های نسخه فعلی نیستند.

## محیط آزمایش
- بک‌اند: `uvicorn app.main:app` روی `127.0.0.1:8000`
- فرانت‌اند: `vite dev` روی `127.0.0.1:5173` (پروکسی `/api` و `/ws` و `/media`)
- مرورگر: پنل مدیریت + دو تب «صفحه نمایش» هم‌زمان

## آزمایش‌های مدل «لینک مشترک» (نسخه ۱.۱) ✓

تاریخ: همراه با تغییر به URL اشتراکی `/display` (بدون توکن برای هر نمایشگر)

| # | آزمایش | نتیجه |
|---|---|---|
| ۱۷ | دو tab مستقل، هر دو دقیقاً `http://127.0.0.1:5173/#/display` | ✓ هر دو بارگذاری و متصل شدند؛ سرور «connected: 2» گزارش کرد |
| ۱۸ | حذف full توکن/`?id=`: صفحه نمایش بدون پارامتر کار می‌کند، پنل «نمایشگرها» فقط لینک مشترک + QR + شمارنده اتصال را نشان می‌دهد | ✓ |
| ۱۹ | امنیت: `/api/public/display` فقط فیلدهای عمومی را می‌دهد (بدون رمز/فیلدهای داخلی)؛ مسیرهای admin بدون توکن → 401 | ✓ |
| ۲۰ | حالت همگام (synchronized, 5s): ثبت هم‌زمان هر دو tab — تغییر اسلاید در هر دو دقیقاً در همان ثانیه (464, 469, 474) | ✓ در یک پنجره ۲۰ ثانیه‌ای، ثانیه‌های همپوشانی هر dua tab یکسان |
| ۲۱ | پیوستن تازه‌وارد: tab بارگذاری‌مجدد وسط اسلاید فوراً به اسلاید جاری مشترک پیوست و ادامه چرخه مطابق tab دیگر بود | ✓ |
| ۲۲ | به‌روزرسانی قیمت (قیمت قهوه → ۳۴۵,۰۰۰ تومان) از API → هر دو tab بدون رفرش قیمت جدید را نشان دادند | ✓ (۳۴۵٬۰۰۰ تومان در هر دو) |
| ۲۳ | حالت مستقل (independent): هر دو tab محтоп داده مشترک دارند اما موقعیت اسلاید جداگانه می‌چرخند (۲/۳، ۱/۳ متفاوت در همان لحظه) | ✓ |
| ۲۴ | شمارنده «۱/۲ تلویزیون متصل» در پنل نمایشگرها با اتصال/قطع هر tab به‌صورت زنده تغییر می‌کند | ✓ |
| ۲۵ | typecheck فرانت‌اند `tsc --noEmit` بدون خطا پس از همه تغییرات | ✓ |

- مرورگر واقعی تلویزیون دوو DSL-50MS3000U در دسترس نبود؛ صفحه نمایش در مرورگر
  دسکتاپ (Chrome) آزمایش شد. سازگاری تلویزیون به‌طور مشخص باید روی دستگاه واقعی بررسی شود؛
  در صورت ناسازگاری، مسیر جایگزین (لپ‌تاپ/مینی‌PC HDMI) در TV-CONNECTION.md آمده است.
- استقرار روی سرور آنلاین/دامنه/HTTPS در این محیط انجام نشد؛ راهنمای کامل در
  DEPLOYMENT.md آمده است.

  برای بارگذاری با میزان واقعا بالا (مایک‌ها داده) مهاجرت به Postgres لازم است.
